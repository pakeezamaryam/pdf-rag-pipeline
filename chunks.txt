19. RAG Implementation Notes
Stage 1 — Extract
Use a Python PDF library such as pypdf or pdfplumber to read the document. Extract text page by page
and preserve page numbers as metadata.
Stage 2 — Clean
Remove unnecessary repeated whitespace while keeping headings and paragraph boundaries where
possible. Cleaning should improve consistency without destroying useful information.
Stage 3 — Chunk
Split the extracted text into manageable pieces. A simple word-based approach can start with 300–500
words per chunk and 50–100 words of overlap.
Stage 4 — Embed
Convert each chunk into a

words per chunk and 50–100 words of overlap.
Stage 4 — Embed
Convert each chunk into a numerical embedding using an embedding model. The embedding captures
semantic information so related questions and passages can be compared.
Stage 5 — Store
Store each embedding with its text and metadata in a vector database such as Chroma, FAISS, Qdrant,
Weaviate, or Pinecone.
Stage 6 — Retrieve
When a user asks a question, create an embedding for the question, search for similar document
chunks, and return the highest-quality matches to the language model.
Stage 7 — Evaluate
Test the system with questions whose answers appear in different sections. Check whether retrieved
chunks contain enough context and whether overlap improves answers
